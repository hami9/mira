# دستیار هوشمند

[English](ai-assistant.md) · **فارسی**

میرا از اطلاعات تأییدشده فروشگاه پاسخ می‌دهد و می‌تواند محصولات ووکامرس را به شکل کارت معرفی کند.

## راه‌اندازی

۱. مایگریشن‌ها را اجرا و API، پردازشگر، داشبورد و ویجت را با هم به‌روز کنید. مایگریشن
`1737300800000-AiAssistant` تنظیمات منابع، اطلاعات تکمیلی پیام و توقف پایدار ربات را اضافه می‌کند.

۲. ارائه‌دهنده و کلید مدل در متغیرهای محیطی سرور تنظیم می‌شوند. شناسه مدل گفتگو در پنل قابل
تغییر است. مدل بردارسازی همچنان از تنظیمات سرور و بردارهای ۷۶۸ بعدی استفاده می‌کند.

۳. در **تنظیمات ← مرکز هوش مصنوعی** هویت، خوش‌آمدگویی، شروع‌های پیشنهادی، لحن، پیام تحویل،
مدل، خلاقیت و سقف پاسخ را تنظیم کنید. پیش‌نمایش پنل فقط ظاهر را نشان می‌دهد؛ آزمون واقعی از ویجت است.

۴. اسناد پایگاه دانش باید به وضعیت آماده برسند. منابع دلخواه را فعال کنید: اسناد، صفحه‌های عمومی
وردپرس، محصولات ووکامرس یا متن اطلاعات تأییدشده سرور. در این متن فقط اطلاعات قابل ارائه به مشتری بنویسید.

۵. برای منابع زنده، افزونه به‌روز میرا را نصب و آدرس HTTPS عمومی و کلید مشترک وردپرس را ذخیره کنید.
کلید ذخیره‌شده به مرورگر برنمی‌گردد؛ خالی گذاشتن ورودی آن را حفظ می‌کند. منابع زنده پیش‌فرض خاموش‌اند.

## مصرف و اعتبار

مدیر در **تنظیمات ← هزینه و اعتبار آوالای** مصرف توکن، درخواست ناموفق، تعداد کاربران، میانگین
توکن هر کاربر و هزینه نهایی را در بازه ۱، ۷ یا ۳۰ روز می‌بیند. جدول، ۱۰۰ بازدیدکننده پرمصرف را
نشان می‌دهد؛ آمار کل شامل همه است. پاسخ، بازیابی، پیشنهاد اپراتور و خلاصه به بازدیدکننده گفتگو
نسبت داده می‌شوند. بردارسازی اسناد فقط در مجموع سایت می‌آید. هر بازدیدکننده، شناسه مرورگر است؛
تعداد افراد واقعی بین چند دستگاه نیست. مایگریشن `1737300900000-AiUsage` ثبت مصرف را شروع می‌کند؛
اطلاعات گذشته بازسازی نمی‌شود. مقدار نامعلوم صفر نیست و میانگین با مصرف ناقص محاسبه نمی‌شود.

در `.env` سرور، `AI_PROVIDER=openai` و متغیرهای `AVALAI_API_KEY`،
`AVALAI_BASE_URL=https://api.avalai.ir/v1`، `AVALAI_MODEL=deepseek-v4-flash` و
`AVALAI_SITE_ID` با UUID سایت را تنظیم کنید. برای انتخاب آوالای، `OPENAI_API_KEY` خالی باشد؛
کلید صریح OpenAI اولویت دارد. Docker این فایل را به API و پردازشگر می‌دهد؛ هر دو باید دوباره ساخته
و اجرا شوند. فایل `.env.avalai.local` فقط برای اسکریپت آزمون است، وارد گیت نمی‌شود و برنامه آن را
خودکار نمی‌خواند.

اتصال حساب به سایت برای نمایش اطلاعات مالی اجباری است؛ سایت دیگر موجودی حساب را نمی‌بیند.
نقش مدیر با هر درخواست از دیتابیس تازه خوانده می‌شود و کلید هرگز به مرورگر برنمی‌گردد.
گزارش توکن محلی بدون آوالای هم کار می‌کند. موجودی و گزارش ۲۴ ساعت کل حساب از
[User API آوالای](https://docs.avalai.ir/en/api-reference/user) با کش دو دقیقه خوانده می‌شود؛
مصرف کل حساب ممکن است برنامه‌های دیگر را هم شامل شود.

شناسه `avalai-request-id` درخواست موفق ذخیره می‌شود. با بازکردن یا به‌روزرسانی بخش هزینه،
حداکثر ۱۰۰ تراکنش در انتظار که بیش از ۳۰ ثانیه عمر دارند تطبیق داده می‌شوند. مقدار `cost.unit`
هزینه نهایی دلاری است، نه تخمین از اختلاف موجودی. هزینه ناموجود در انتظار می‌ماند. برای ارائه‌دهنده
دیگر یا درخواست بدون این هدر، فقط مصرف توکن ثبت می‌شود. تطبیق زمان‌بندی‌شده وجود ندارد؛ برای
هزینه‌های دیرهنگام پنل را بعداً به‌روز کنید.

محاسبه‌گر از تعرفه زنده متن به ازای یک میلیون توکن و نرخ زمینه بلند استفاده می‌کند؛ تخفیف کش،
بسته اعتباری و ابزار در برآورد نیست. پرداخت سریع صفحه رسمی آوالای را باز می‌کند و پرداخت را کاربر
آنجا تکمیل می‌کند.

## منابع و محدودیت‌ها

- مسیر ثابت `/wp-json/mira/v1/ai-context` با هدر `X-Mira-Api-Key` خوانده می‌شود. فقط نوشته و
  صفحه عمومی بدون رمز و محصول قابل‌مشاهده و قابل‌خرید برمی‌گردد. قیمت با تنظیم مالیات نمایشی ووکامرس
  هماهنگ است؛ محصول متغیر با «از» نمایش داده می‌شود. خرید در صفحه محصول انجام می‌شود.
- فقط HTTPS عمومی روی پورت ۴۴۳ پذیرفته می‌شود. شبکه داخلی، پاسخ DNS ترکیبی عمومی/خصوصی،
  آدرس دارای رمز و ریدایرکت رد می‌شوند. IP تا پایان درخواست ثابت می‌ماند و حجم و زمان پاسخ محدود است.
  اطلاعات سرور داخلی از متن تأییدشده یا پایگاه دانش تأمین می‌شود؛ اجرای فرمان و خواندن URL دلخواه وجود ندارد.
- کوئری‌های ربات به سایت محدودند. منابع و تاریخچه، داده غیرقابل‌اعتماد هستند و دستور سیستم نمی‌شوند.
  خروجی JSON فقط می‌تواند شناسه منابع و محصولات واقعی را انتخاب کند. کارت و لینک را سرور می‌سازد.
- موضوع‌های ممنوع با تطبیق متن بررسی می‌شوند، نه مدل تشخیص معنایی. الگوهای رایج ایمیل، تلفن و
  کلید از متن گفتگو و زمینه حذف می‌شوند. این روش همه اطلاعات حساس را تشخیص نمی‌دهد و صحت همه
  پاسخ‌ها را تضمین نمی‌کند. اطمینان مدل، تخمین خودش است؛ آستانه ارتباط اسناد مستقل تنظیم می‌شود.
- درخواست انسان، کمبود منبع، پاسخ نامعتبر، خطای ارائه‌دهنده یا رسیدن به سقف پاسخ، ربات را برای
  همان گفتگو متوقف می‌کند. اپراتور می‌تواند ادامه دهد. بستن و بازکردن همان گفتگو توقف را حفظ می‌کند؛
  گفتگوی جدید تابع تنظیمات جاری سایت است.
- قفل گفتگو و شناسه ثابت پاسخ مانع پیام تکراری می‌شوند. پیش از ثبت، ورود اپراتور، پیام جدید،
  حل گفتگو و خاموش‌شدن AI دوباره بررسی می‌شوند.
- انیمیشن، مرحله واقعی بررسی منابع و تولید پاسخ را نشان می‌دهد و افکار خصوصی مدل نیست.
  سقف نمایش ۶۰ ثانیه است. قطع اتصال و پایان پاسخ آن را پاک می‌کند. تاریخچه تکراری نمی‌شود و ارسال
  ناموفق، متن پیش‌نویس را نگه می‌دارد.

## آزمون

```bash
npm ci
npm run build
npm run lint
npm run format:check
npm test
npm run test:integration
```

آزمون یکپارچگی به Postgres موقت با pgvector و اجرای مایگریشن نیاز دارد. مدل و بردارسازی در آن
جایگزین قطعی دارند. آزمون مرورگر AI به API، Redis و پردازشگر واقعی نیاز دارد؛ فایل
`tests/fixtures/ai-provider.mjs` ارائه‌دهنده آزمایشی است. آدرس آن را با
`OPENAI_BASE_URL=http://127.0.0.1:4201/v1`، کلید `OPENAI_API_KEY=fixture-only` و
گزینه `AI_E2E=1` فعال کنید. CI این مسیر را اجرا می‌کند؛ نتیجه آزمون، کیفیت یک مدل تجاری را ثابت نمی‌کند.

برای آزمون واقعی افزونه، استک جداگانه `tests/fixtures/wordpress.yml` را بالا بیاورید، وردپرس و
ووکامرس را نصب و میرا را فعال کنید. سپس اجرا کنید:

```bash
docker compose -f tests/fixtures/wordpress.yml run --rm cli eval-file /tmp/wordpress-check.php
docker compose -f tests/fixtures/wordpress.yml down -v
```

فایل تست نوشته‌های خودش را حذف و کلید قبلی را بازمی‌گرداند. دستور آخر فقط استک موقت و حجم آن را پاک می‌کند.
قرارداد داده مطابق [کنترل دسترسی WP_Query](https://developer.wordpress.org/reference/classes/wp_query/)
و [اطلاعات محصول ووکامرس](https://woocommerce.github.io/code-reference/classes/WC-Product.html) است.

اسکریپت `tests/fixtures/avalai-usage.mjs` پس از build، با دیتابیس موقت مایگریشن‌شده در
`TEST_DATABASE_URL`، Redis و فایل کلید محلی اجرا می‌شود. یک درخواست پولی از صف ارسال می‌کند،
مصرف کاربر، اعتبار و هزینه نهایی را بررسی و داده‌های خودش را حذف می‌کند. صف پیشوند مستقل دارد.
اسکریپت `avalai-check.mjs` سه پاسخ مدل را جداگانه می‌آزماید؛ CI فقط ارائه‌دهنده قطعی رایگان دارد.

در ۲۰۲۶/۱۰/۲۲ مدل `deepseek-v4-flash` برای ارسال، انتخاب محصول و نبود منبع آزموده شد.
یک درخواست جداگانه از صف، ۳۸۵ توکن ورودی، ۱۰۱ خروجی و هزینه نهایی ۰٫۰۰۰۱۱۸۳ دلار ثبت کرد.
این آزمون محدود عملکردی است؛ Luna و استقرار عمومی روی سرور هنوز بررسی نشده‌اند.

## هویت هر فروشگاه

نام فروشگاه در بخش هویت AI قابل ویرایش است. نشست ویجت فقط نام عمومی و هویت دستیار همان
سایت را دریافت می‌کند. پردازشگر برای پاسخ، پیشنهاد اپراتور و خلاصه، نام همان سایت را می‌خواند؛
اسناد، محصولات و مصرف هم به همان سایت محدود می‌مانند. نام سایت‌های موجود خودکار عوض نمی‌شود.
سایت نمونه جدید و صفحه دمو از برند میرا استفاده می‌کنند. شناسه‌های قدیمی ورود و کلید ویجتِ توسعه
برای سازگاری ارتقا باقی مانده‌اند و هویت فروشگاه مشتری نیستند.

آزمون مرورگر دو فروشگاه مستقل با کلیدهای متفاوت را باز و نام درست را در سربرگ و پاسخ صف بررسی
می‌کند. این تست مسیر سایت و زمینه مدل است؛ تضمین نمی‌کند مدل هیچ‌وقت نامی را اشتباه نگوید.

برای دو فروشگاه مستقل، رکورد سایت و کلید ویجت جدا و دامنه مجاز همان فروشگاه لازم است. اشتراک
یک کلید بین دو فروشگاه نامرتبط، عمداً به معنی یک هویت و فضای گفتگو است. نشست فعلی داشبورد
متعلق به یک سایت است؛ جابه‌جایی مرکزی حساب‌ها و ساخت مشتری سرویس میزبانی‌شده جزو این تغییر
نیست. `SEED_SITE_NAME` فقط نام سایت تازه‌ساخته‌شده را تعیین می‌کند.
