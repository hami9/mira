# میزبانی میرا

[English](HOSTING.md) · **فارسی**

همه امکانات موجود در نسخه خودمیزبان بدون اشتراک، فعال‌سازی و لایسنس پولی میرا در دسترس‌اند.
هزینه سرور و سرویس هوش مصنوعی جداست. سازنده: **hami9 — https://hami9.ir**.
مجوز برنامه AGPL-3.0 و افزونه وردپرس GPLv2+ باقی می‌ماند؛ [NOTICE](../NOTICE) را ببینید.

## انتخاب روش نصب

| امکانات میزبان                                                                        | روش نصب                                                               |
| ------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| سرور لینوکس با Docker                                                                 | فایل مستقل کم‌مصرف؛ وب‌سرور موجود HTTPS را مدیریت می‌کند              |
| cPanel یا DirectAdmin با Node.js، نصب npm، پردازش دائمی، PostgreSQL با vector و Redis | بارگذاری بسته و اجرای `app.cjs` از پنل، بدون SSH کاربر                |
| هاست اشتراکی PHP/MySQL                                                                | نصب افزونه وردپرس یا کد ویجت؛ موتور میرا روی میزبان دیگری اجرا می‌شود |

نام کنترل‌پنل به‌تنهایی تضمین اجرای Node.js، Redis، PostgreSQL، WebSocket یا پردازشگر نیست.
قبل از نصب کامل از ارائه‌دهنده درباره این امکانات بپرسید. موتور فعلی PHP/MySQL نیست و این
نسخه موتور دوم PHP پیاده‌سازی نمی‌کند.

## سرور کم‌مصرف کنار سایت

`docker-compose.lite.yml` فایل مستقل است و نباید مثل overlay روی فایل اصلی گذاشته شود.
چهار سرویس PostgreSQL، Redis، API با داشبورد استاتیک و پردازشگر صف را اجرا می‌کند. MinIO
که برای پیوست‌های آینده رزرو شده و سرویس‌های جداگانه Vite، nginx و Caddy اجرا نمی‌شوند.
هیچ امکانات نسخه نصبی به پرداخت اشتراک وابسته نیست.

در نصب جدید بسته دبیان، `sudo mira setup --lite` و سپس `sudo mira start` را اجرا کنید.
در نصب موجود، اجرای دوباره setup تنظیمات را جایگزین می‌کند؛ برای تغییر سقف منابع فقط فایل
تنظیمات را ویرایش کنید. جابه‌جایی به پروفایل سبک باید با بک‌آپ و حفظ نام پروژه و volumeهای
قبلی انجام شود تا به دیتابیس خالی دیگری وصل نشوید. دستورات `mira resources`، `mira backup`،
`mira restore` و `mira doctor` با این پروفایل کار می‌کنند.

برای سورس، `.env.example` را به `.env` کپی کنید، رمزهای واقعی و seed را تنظیم کنید و
`DATABASE_URL` را به `postgres:5432` بدهید. `PUBLIC_API_URL`، `DASHBOARD_URL` و
`CORS_ALLOWED_ORIGINS` باید آدرس HTTPS یکسان میرا باشند. دامنه سایت و خود میرا را در
`SEED_ALLOWED_DOMAINS` بگذارید:

```bash
docker compose -f docker-compose.lite.yml up -d --build
# برای ایمیج نسخه‌ای که این قابلیت را دارد، بدون ساخت روی سرور:
docker compose -f docker-compose.lite.yml up -d --no-build
docker compose -f docker-compose.lite.yml stats --no-stream
```

سقف پیش‌فرض حافظه کانتینرها: API برابر ۳۸۴، پردازشگر ۲۵۶، PostgreSQL برابر ۳۸۴ و Redis
برابر ۱۹۲ مگابایت دودویی؛ جمع سقف‌ها ۱۲۱۶ MiB است. **این عدد مصرف اندازه‌گیری‌شده یا حافظه
رزروشده نیست.** برای شروع حداقل ۲ GiB برای میرا و سیستم‌عامل در نظر بگیرید و برای سایت و
برنامه‌های دیگر فضای بیشتری کنار بگذارید. ساخت ایمیج حافظه اضافه می‌خواهد؛ برای سرور شلوغ
ایمیج آماده بهتر است. سقف‌ها را بعد از اندازه‌گیری بار واقعی کاهش دهید.

پیش‌فرض اتصال دیتابیس API پنج و پردازشگر سه است. `WORKER_CONCURRENCY=2` سقف مشترک هر پنج
صف است. متغیرهای `API_MEMORY_LIMIT`، `WORKER_MEMORY_LIMIT`، `POSTGRES_MEMORY_LIMIT`،
`REDIS_MEMORY_LIMIT` و همتای `*_CPU_LIMIT` سقف کانتینرها را تغییر می‌دهند. Redis داده را
پایدار می‌کند و `noeviction` دارد: هنگام پرشدن حافظه، نوشتن خطا می‌دهد و کارهای صف را
بی‌صدا پاک نمی‌کند. قبل از پرشدن ظرفیت را افزایش دهید. لاگ هر کانتینر دو فایل پنج‌مگابایتی
دارد؛ تاریخچه گفتگو برای کم‌کردن مصرف حذف نمی‌شود. بک‌آپ دوره‌ای PostgreSQL را خودتان
تنظیم کنید؛ این پروفایل کانتینر بک‌آپ زمان‌بندی‌شده overlay تولید را اجرا نمی‌کند.

تنها پورت در دسترس `127.0.0.1:3300` است و با `MIRA_HTTP_PORT` تغییر می‌کند. پورت دیتابیس و
Redis عمومی نیست. میرا پورت ۸۰/۴۴۳ را اشغال نمی‌کند و تنظیم سایت موجود را تغییر نمی‌دهد.
نمونه وب‌سرور Caddy موجود:

```caddy
chat.example.com {
    reverse_proxy 127.0.0.1:3300
}
```

نمونه nginx برای virtual host مجزایی که HTTPS آن از قبل تنظیم شده:

```nginx
location / {
    proxy_pass http://127.0.0.1:3300;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 120s;
}
```

می‌توان از زیردامنه سایت، دامنه دیگر یا آدرس HTTPS ارائه‌شده توسط میزبان استفاده کرد.
میرا دامنه خاصی تحمیل نمی‌کند و دامنه نمی‌فروشد. برنامه باید روی ریشه آدرس باشد؛ اجرای کل
برنامه زیر مسیر `/mira` پشتیبانی نمی‌شود. HTTP/IP برای تست خصوصی مناسب است؛ نصب عمومی
برای ورود امن و قابلیت‌های مرورگر به HTTPS نیاز دارد. چند نصب باید نام پروژه Compose،
پورت، volume، دیتابیس و فضای صف جدا داشته باشند.

## cPanel و DirectAdmin بدون SSH

بسته را با `npm ci && npm run package:hosting` روی کامپیوتر توسعه بسازید یا فایل
`mira-hosting-<version>.tar.gz` را از نسخه‌ای که آن را دارد بگیرید. کد کامپایل‌شده، داشبورد،
ویجت، migrationها، مجوز و ابزار تنظیمات داخل آن است؛ وابستگی production روی هاست نصب
می‌شود و TypeScript روی هاست کامپایل نمی‌شود.

۱. بسته را روی کامپیوتر استخراج و `mira/configure.html` را محلی باز کنید. دیتابیس خالی
مخصوص میرا با pgvector، Redis، نام فروشگاه، حساب مدیر و آدرس عمومی HTTPS را وارد کنید.
`mira.env` را دریافت کنید؛ این صفحه هیچ درخواست شبکه‌ای ندارد.

۲. از File Manager بسته را در پوشه خصوصی برنامه **بیرون public_html** بارگذاری و استخراج
کنید. `mira.env` را همان‌جا به `.env` تغییر نام دهید و فقط به صاحب برنامه دسترسی فایل
بدهید. کل پوشه برنامه نباید مثل فایل استاتیک سایت در دسترس وب قرار بگیرد.

۳. در cPanel از Application Manager یا Setup Node.js App ارائه‌دهنده استفاده کنید:
Node.js نسخه ۲۲٫۱۲ یا جدیدتر، حالت production، پوشه خصوصی، فایل شروع `app.cjs` و دامنه HTTPS
روی ریشه. با Enable Dependencies یا Run NPM Install وابستگی‌ها را نصب کنید. اگر پنل فقط
`app.js` می‌پذیرد، نام `app.cjs` را به `app.js` تغییر دهید؛ بسته CommonJS است. `.npmrc`
بسته، وابستگی‌های توسعه را نصب نمی‌کند.

۴. در DirectAdmin اگر ارائه‌دهنده Setup Node.js App دارد همان مسیر را بروید. گزینه Nginx
Unit علاوه بر Node به نصب وابستگی و launcher سازگار نیاز دارد؛ **اجرای این launcher مخصوص
Passenger روی Unit تأیید نشده است** و صرف وجود منوی Unit به معنی سازگاری نیست.

۵. در پنل `NODE_OPTIONS=--max-old-space-size=256` بگذارید. یک نمونه همیشه‌روشن، اجازه
child process و WebSocket یا polling صحیح Socket.IO با sticky session لازم است. تعلیق
برنامه در حالت بی‌کاری باید توسط میزبان غیرفعال شود. اگر مجاز نیست، موتور را جای دیگری
نصب کنید؛ درخواست cron جای پردازشگر دائمی را نمی‌گیرد.

۶. برنامه را Start/Restart کنید. `app.cjs` migration و seed کامپایل‌شده را اجرا می‌کند و
سپس API و پردازشگر مستقل صف را بالا می‌آورد. `/health` و سپس `/` را باز کنید و وارد شوید.
داشبورد، API، ویجت و `/chat.html?key=...` هم‌آدرس هستند و SSL را پنل مدیریت می‌کند.

۷. در تنظیمات میرا شناسه سایت را بردارید و در `SYSTEM_SITE_ID` فایل خصوصی `.env` بگذارید،
سپس Restart کنید تا آمار منابع فعال شود. برای آوالای، کلید و `AVALAI_SITE_ID` را مشابه
تنظیم کنید.

برای به‌روزرسانی، ابتدا بک‌آپ بگیرید؛ `.env`، دیتابیس و داده پایدار Redis را نگه دارید،
فایل‌های برنامه را جایگزین، وابستگی production را نصب و برنامه را Restart کنید. تغییر
کلید seed یا استفاده از دیتابیس خالی روش به‌روزرسانی نیست.

مراجع رسمی: [Application Manager سی‌پنل](https://docs.cpanel.net/cpanel/software/application-manager/)،
[Nginx Unit دایرکت‌ادمین](https://docs.directadmin.com/webservices/nginx_unit/) و
[چرخه اجرای Passenger](https://www.phusionpassenger.com/docs/advanced_guides/config_and_optimization/standalone/optimization.html).
مسیر بسته به امکانات میزبان وابسته است؛ استقرار روی حساب واقعی cPanel/DirectAdmin و قوانین
پردازش و SSL همان ارائه‌دهنده همچنان باید آزمایش شود.

## اتصال و شخصی‌سازی

از «تنظیمات ← نصب و شخصی‌سازی» دامنه‌های مجاز، رنگ و محل ویجت را تغییر دهید و کد نصب یا
لینک مستقیم گفتگو بگیرید. برای لینک مستقیم، دامنه خود میرا باید در دامنه‌های مجاز سایت
باشد. نام دستیار، خوشامد، سوال‌های پیشنهادی، منابع، گاردریل و مدل از بخش AI قابل تنظیم‌اند
و تنظیمات هر فروشگاه جداست.

افزونه وردپرس را از «افزونه‌ها ← افزودن ← بارگذاری» روی هر هاست وردپرسی نصب و آدرس موتور
و کلید ویجت را وارد کنید؛ SSH روی میزبان سایت لازم نیست. این کار سایت را به میرا متصل
می‌کند و Node.js داخل وردپرس نصب نمی‌کند.

بخش «منابع و سلامت اجرا» حافظه RSS و CPU پردازش API و worker، حجم دیتابیس و سقف‌ها را
با درخواست کاربر نشان می‌دهد. نقش مدیر از دیتابیس تازه بررسی و `SYSTEM_SITE_ID` دقیق
تطبیق داده می‌شود. آمار مدیر میزبان برای مدیر فروشگاه دیگر باز نیست. Docker socket، شل
راه دور، پنل پولی یا سرویس تله‌متری بیرونی استفاده نمی‌شود.
